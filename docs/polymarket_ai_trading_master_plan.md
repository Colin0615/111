# AI 驱动 Polymarket 交易系统：研究级策略 + 可落地实施方案（v2）

> 目标：在严格风控下，从 **$50 小额试验** 启动，建立“可回测、可复盘、可持续进化”的 AI 交易系统。

---

## 1) 先说结论（给你可直接执行的版本）

如果你只想马上开干，用这个：

- **市场范围**：前 6 周主做高流动市场（如 BTC/ETH 方向盘），只用 20% 资金做跨主题探索。
- **策略结构**：`事件驱动(新闻/情绪) + 盘口微结构 + 赔率一致性` 三模型投票。
- **执行方式**：以限价单为主，严禁追高吃单；单笔风险 ≤ 1.5%，日亏损 4% 即停机。
- **训练/迭代**：每周只改 1-2 个参数组，必须先过回测+模拟门槛再上实盘。
- **自学习机制**：用“实验注册表 + 版本晋升 + 失败样本库 + 自动回滚”闭环。

## 2) 深度研究后的关键认知（策略设计依据）

## 2.1 平台机制约束（决定能不能做、怎么做）

1. Polymarket CLOB 是“链下撮合 + 链上结算”的混合式结构，订单为 EIP-712 签名消息。程序化交易推荐优先使用官方 SDK。  
2. CLOB 鉴权分两层：L1（私钥签名导出凭证）+ L2（HMAC）用于下单/撤单等请求。  
3. 费用结构并非固定常量，不同品类不同费率，且文档注明 **2026-03-30 起**有新的费率参数，需要在策略里做“类别化成本模型”。  
4. 地理限制与合规条款严格，且平台明确禁止 VPN 绕过；策略设计必须先满足合规前提。

> 这几条会直接影响你的执行引擎、回测成本模型、可交易市场池。

## 2.2 微结构研究启发（为什么要看盘口不只看新闻）

- 队列不平衡（queue imbalance）对下一跳 mid-price 方向有显著预测力。 
- 在中观尺度上，订单流（新增/撤单）与更深层 LOB 形状，往往比“单一 top-of-book 失衡”更有预测力。

> 所以你的模型不能只用“bid-ask 差”和“涨跌新闻”，必须把 **深度、撤单率、订单流斜率** 纳入特征。

## 2.3 情绪研究启发（新闻模型容易踩的坑）

- 近期研究指出：把大量新闻情绪粗暴平均会导致“情绪同质化”，会抹平有用信号；应该做来源质量加权与动态聚合。

> 所以你的情绪模型必须：
- 做来源可信度分层；
- 做时间衰减；
- 做“事件级聚合”而不是“全局平均”。

## 3) 交易系统总体架构（生产级）

```text
[News/Social Feeds] ----> [事件抽取+情绪引擎] --┐
                                                   ├--> [信号融合层] --> [风险引擎] --> [执行引擎] --> Polymarket CLOB
[Polymarket Market/Book] -> [盘口微结构引擎] ----┘

[历史库/特征库] <--> [回测引擎] <--> [实验管理器] <--> [模型注册表]
                                      |
                                      +--> [复盘与错误归因]
```

模块说明：
1. **事件情绪引擎**：把新闻流转换为“可交易事件”。
2. **盘口微结构引擎**：秒级提取深度形状、失衡、冲击、成交质量因子。
3. **信号融合层**：输出方向概率 + 置信度 + 失效时间（TTL）。
4. **风险引擎**：仓位、相关性、回撤、异常波动统一约束。
5. **执行引擎**：限价优先、撤单重报、价格保护、熔断。
6. **实验管理器**：自动 A/B + 回测门槛 + 策略版本晋升。

## 4) 策略库（从“能赚钱”角度组织）

## 4.1 策略A：事件驱动（News-to-Market）

**输入**：标题、正文、发布时间、来源、实体（人/机构/地区）、事件类型。  
**输出**：
- `p_up`: 事件导致 YES 概率上升的概率
- `impact_half_life`: 预估冲击衰减半衰期
- `source_conf`: 来源可信分

**规则模板（v1）**：
- 当 `p_up > 0.62` 且 `source_conf > 0.7` 且盘口未完全定价（盘口确认条件未触发）→ 试探开仓。
- 若 3~8 分钟内成交量与价格同向确认 → 允许一次加仓。
- 若盘口出现反向大单 + 深度塌陷 → 强制止损。

## 4.2 策略B：盘口微结构（LOB Alpha）

核心特征（最少集）：
- `QI1`: best bid/ask queue imbalance
- `DepthSlope`: 前 N 档深度斜率
- `CancelPressure`: 撤单率(ask)/撤单率(bid)
- `TradeSignImb`: 主动买卖成交差
- `SpreadState`: 点差状态（收敛/扩张）

**信号模板**：
- 当 `QI1 + DepthSlope + TradeSignImb` 综合评分超过阈值，且点差可承受 → 限价挂单。
- 对小资金，优先“低冲击成交质量”，宁可少做，不追单。

## 4.3 策略C：赔率一致性 / 弱套利

- 同一事件 YES/NO 概率和偏离检查；
- 跨相关市场（同主题）概率关系一致性检查；
- 出现明显偏离时做小仓位纠偏单，优先快进快出。

## 4.4 策略D：临近结算时间衰减

- 离结算越近，新信息边际影响下降；
- 通过 `time_to_resolution` 调整仓位上限与止盈止损参数；
- 临近结算不做低流动追单。

## 5) 50美元资金的“实战参数”

## 5.1 组合分配（建议）

- 70%：高流动主策略（BTC/ETH 方向盘）。
- 20%：跨主题探索（政治/经济/科技事件）。
- 10%：保留为风险缓冲，不主动出手。

## 5.2 风控硬规则

- 单笔风险 ≤ 1.5%（$0.75）。
- 单市场敞口 ≤ 15%（$7.5）。
- 强相关市场总敞口 ≤ 35%。
- 日亏损 ≥ 4%：当天停机。
- 周亏损 ≥ 10%：退回模拟模式至少 3 天。
- 连续 5 笔亏损：强制人工复盘。

## 5.3 成本与滑点模型（必须）

按市场类别维护费用参数表（Crypto/Sports/Politics...），并按文档给定公式计算。

```text
fee = C × p × feeRate × (p × (1 - p))^exponent
```

回测里必须把：
- taker 费、maker rebate（如适用）、点差冲击、部分成交损耗全部纳入。

## 6) 回测与模拟：怎么避免“看起来能赚、实盘亏钱”

## 6.1 数据切分

- 训练窗口：滚动 60-120 天；
- 验证窗口：最近 14-30 天；
- 必做 walk-forward（滚动前推），禁止一次性静态切分。

## 6.2 防数据泄漏

- 新闻必须使用“发布时刻可见数据”；
- 盘口特征只能基于当前及历史，不可偷看未来成交；
- 结算信息只用于标签，不可进入当期特征。

## 6.3 评估指标（不仅看收益）

收益类：净收益、胜率、盈亏比。  
风险类：最大回撤、连续亏损长度、尾部损失。  
执行类：成交率、撤单率、平均滑点、信号到下单延迟。  
概率类：Brier score、log loss（检验概率是否校准）。

## 6.4 上线门槛（建议硬阈值）

必须同时满足：
1. 30 天模拟净收益 > 0；
2. 最大回撤 < 15%；
3. 成交质量劣化不超过基线 10%；
4. Brier score 持续优于朴素基线。

## 7) 自我学习机制（你最关心）

## 7.1 实验流水线（AutoResearch 化）

每日循环：
1. 选 1 个假设（例如“情绪衰减从 4h 改为 2h”）；
2. 生成实验配置（唯一 ID）；
3. 回测 + 模拟双检验；
4. 自动写入实验报告；
5. 达标才申请晋升版本。

## 7.2 版本治理

- `research/experiments/*.yaml`：参数与假设。
- `research/reports/*.md`：结果与结论。
- `models/registry.json`：当前线上版本、回滚版本、发布时间。

## 7.3 错误学习（Failure Library）

对每笔亏损单自动归因：
- 信号错（方向错）
- 时机错（太早/太晚）
- 执行错（滑点/漏单）
- 风控错（仓位过大）

每周聚合 top-3 失败模式，转成下周实验优先级。

## 13) 你这条反馈的核心：哪些模块应该由大模型主导？

你说得对：**很多模块用大模型会更强**。但最佳实践不是“全LLM”，而是 **LLM + 规则引擎 + 统计模型** 的混合架构。

### 13.1 建议的 LLM 主导模块（高收益）

1. **事件理解层（强烈建议 LLM）**  
   - 任务：新闻去重、事件抽取、因果链解释、冲突信息识别。  
   - 输出：`event_id, event_type, actors, direction_hint, confidence, evidence`。

2. **情绪与叙事层（建议 LLM）**  
   - 任务：识别市场叙事变化（risk-on/risk-off）、判断“情绪是否过热”。  
   - 关键：必须要求模型输出“证据句 + 来源置信分”。

3. **交易理由生成层（建议 LLM）**  
   - 任务：把机器信号转成人类可审计的交易理由。  
   - 输出示例：`为什么买/不买、触发条件、失效条件、最大风险`。

4. **复盘归因层（建议 LLM）**  
   - 任务：读取交易日志后归因（信号错/执行错/风控错），产出下周实验假设。

### 13.2 不建议纯 LLM 的模块（要“确定性优先”）

1. **风控引擎**：仓位限制、回撤阈值、停机规则必须硬编码，不可由 LLM 自由发挥。  
2. **下单执行**：订单参数、重试、撤单、价格保护必须确定性实现。  
3. **PnL 与成本结算**：采用可验证公式，避免 LLM 生成数值逻辑。

### 13.3 推荐的“LLM三层决策协议”

- **LLM-A（研究员）**：做事件与叙事理解，输出结构化信号。  
- **LLM-B（交易员）**：结合盘口与规则，给出候选订单。  
- **LLM-C（审计员）**：只负责反驳与找风险（对抗式审查）。

最后由规则风控层做硬拦截：

```text
if risk_engine.reject(order):
    block_trade()
else:
    execute_limit_order()
```

### 13.4 提升大模型效果的关键做法（实操）

1. **严格结构化输出（JSON Schema）**：避免模型“讲故事”。  
2. **检索增强（RAG）**：新闻判断前先检索历史相似事件与结果。  
3. **多模型投票**：不同模型/提示词并行，降低单模型偏差。  
4. **置信度校准**：把模型置信分映射到历史命中率（Platt/Isotonic）。  
5. **延迟预算**：给每个步骤设置最大时延，超时走降级策略。  
6. **对抗测试集**：专门加入谣言、反转新闻、标题党样本。

### 13.5 可直接执行的 LLM 落地清单

- 第1周：仅在“事件抽取+情绪打分”启用 LLM；交易仍人工确认。  
- 第2-3周：引入 LLM 复盘归因，不参与下单。  
- 第4-5周：LLM 生成候选单，风控硬拦截，模拟盘自动执行。  
- 第6周后：达到门槛再进入小额实盘。

> 结论：你提到“模块都用大模型可能更好”这个方向是对的，
> 但实盘必须采用“LLM 负责认知，规则负责生死”的设计。
